# 迭代记录与自审报告

本文件记录按毕业设计任务书持续迭代的过程，每一轮包含：做了什么、
为什么做、自审结论（是否合理 / 是否必需 / 是否偏离初衷 / 风格一致性 /
工程健壮性）、验证结果。

时间：2026-11-18 夜 至 2026-11-19 凌晨

---

## 审查基线

每轮结束时固定跑：

- `pytest`（当时全部用例）
- 10 个端到端审查脚本（权限矩阵、角色隔离、角色化落地、扩展接口、
  工作台渲染、移动端、二次确认、点评权限、点评闭环、知识库检索）
- `tsc --noEmit` + `vite build`
- CI 四个 job（backend / frontend / e2e / security）

任一项不通过则不提交。

## 第 1 轮：教师点评闭环

**做了什么**：新增 `teacher_comments` 表与管理端点评接口，教师可对学员
单次训练写点评（表现良好 / 需关注 / 需干预），学生在成长中心可见；
学员查看后自动标记已读。

**为什么做**：任务书写"教师查看学员训练记录"，但只解决"看得到"，
教学闭环还缺"给反馈"。这是教师端最实际的缺口。

**自审**
| 维度 | 结论 |
| --- | --- |
| 是否合理 | 合理。教学场景中"看完必须能反馈"是基本闭环 |
| 是否必需 | 必需。没有反馈，教师端只是只读报表 |
| 偏离初衷 | 不偏离。属于任务书"训练端/管理端"的合理延伸 |
| 风格一致 | 点评区块复用全站 tag / mono / paper 体系 |
| 工程健壮 | 越权 403 而非 404（避免泄露记录存在性）；已读标记持久化 |

**过程中修掉的真实缺陷**
1. `comment_service` 只 `flush` 未 `commit`，接口返回 200 但数据丢失。
   根因是 `get_session` 只在异常时回滚、成功路径不提交。
2. 成长中心无本地记录时提前 `return` 空状态，把老师点评一起吞掉——
   学生换设备后看不到反馈。

## 第 4 轮：时间索引 + 前端错误边界

**做了什么**
1. 迁移 0007 为 `training_records.created_at` 建索引
2. 新增 `ErrorBoundary` 包住路由内容

**为什么做**
1. 平台级统计按 `created_at` 范围扫描且不带 `owner_id`，现有复合索引
   `(owner_id, created_at)` 最左列是 owner_id，用不上。EXPLAIN 证实
   MySQL 退化为全索引扫描（`type=index, key_len=133, Using where`）。
   建索引后走 `key_len=5` 的窄索引。
2. 任一组件渲染期抛异常，React 会卸载整棵树，用户只看到白屏。

**自审**
| 维度 | 结论 |
| --- | --- |
| 是否合理 | 合理。索引有 EXPLAIN 证据；白屏是真风险 |
| 是否必需 | 必需。管理端统计是任务书要求，数据量增长后必须有索引 |
| 偏离初衷 | 不偏离。纯工程健壮性，无业务变更 |
| 风格一致 | 兜底页复用 `wb-empty` + `btn-primary/btn-ghost` |
| 工程健壮 | 只包路由内容而非整棵树：页面崩了顶栏还在，可直接换页 |

**验证方式的诚实说明**：临时加 `/__crash` 路由抛异常，用 CDP 实测
兜底页显示、顶栏在、两个按钮有效、点重试后仍可交互。验证完移除探针
并重建，未留在产物里。探针脚本也删除——无法在常规构建中运行，
留着会变成永远跳过的假检查。

## 第 6 轮：端到端审查接入 CI

**做了什么**：新增 `e2e` job（真实 MySQL + 无头 Chrome + 10 个审查脚本）；
把脚本从"只能在 Windows 跑"改成可移植。

**为什么做**：10 个审查脚本此前只在我本地手工跑过——别人把权限改坏了
CI 看不出来。这是最大的工程缺口。

**自审**
| 维度 | 结论 |
| --- | --- |
| 是否合理 | 合理。审查脚本不进流水线等于没有 |
| 是否必需 | 必需。CI 是防回归的唯一自动化手段 |
| 偏离初衷 | 不偏离 |
| 风格一致 | 与既有 CI 三个 job 并列 |
| 工程健壮 | 失败自动 tail 后端日志；两批跑（无浏览器/有浏览器）分离 |

**可移植性改造**
- `ui_smoke`：`CHROME_PATH` 环境变量或 PATH 自动探测；`UI_BASE`、
  `CDP_PORT`、`QA_DIR` 均可配置
- 三个 seed/audit 脚本去掉写死的 `F:\毕业设计` 盘符
- `audit_comments` 从"用 mysql.exe 直查 record_id"改为走 API

**三次失败才跑通，每次都是真问题**
1. `no such table: accounts` —— GitHub Actions 的 step 之间不继承 env，
   `DATABASE_URL` 只在一个 step 里设了。修正：提到 job 级。
2. `No such file: audit_comments.py` —— `.gitignore` 逐个列举白名单，
   新增脚本没加进去。修正：改通配 `!work/*.py`。
3. 本地 10 个审查全绿但 CI 找不到文件——因为本地文件在磁盘上，
   clone 下来才有问题。**这一步才真正验证了"从零拉取能不能跑"**。

## 第 10 轮：标签页键盘可达性与 ARIA 语义

**做了什么**
1. 工作台（4 视图）、管理后台（7 视图）、知识库（2 分类）的标签组
   补齐 WAI-ARIA tabs 模式：方向键、Home/End、焦点跟随、
   `id ↔ aria-controls ↔ aria-labelledby` 关联、非选中 `tabIndex=-1`
2. 修正一处 ARIA 误用：顶栏 `<nav role="tablist">` 改为普通 nav +
   `aria-current="page"`

**为什么做**：只有 `role=tab` 不支持方向键时，键盘用户会被卡住——
每个标签都是一个 tab stop，要按十几次 Tab 才能跳过整组。
顶栏用 tablist 会让读屏念成"标签 3/9"，与"页面跳转"的真实行为不符。

**自审**
| 维度 | 结论 |
| --- | --- |
| 是否合理 | 合理。ARIA 误用属语义错误，不是风格偏好 |
| 是否必需 | 必需。键盘用户与读屏用户能否用是可用性底线 |
| 偏离初衷 | 不偏离。不改变任何业务行为 |
| 风格一致 | 选中态样式沿用原有 `--ink` + 朱红下划线 |
| 工程健壮 | 用 CDP 派发**真实按键**验证，不是 JS 合成事件 |

**两处差点漏掉的连带影响**
1. CSS 选中态选择器写的是 `[aria-selected=true]`，改成
   `aria-current` 后必须同步改 CSS，否则高亮直接消失。
2. 初版按标签分别生成面板 id，但内容是条件渲染的，未激活标签的
   `aria-controls` 指向不存在的元素。改为所有标签指向同一个稳定面板 id。

## 第 11 轮：收敛 Chrome 启动逻辑

**做了什么**：把 9 个审查脚本里各自复制的 Chrome 启动代码收敛为
`ui_smoke.launch_chrome()` + `open_page()`，带容器友好参数与 4 次重试。

**为什么做**：CI 的 e2e 在 `audit_roles_ui` 处失败——
Chrome 已响应 `/json/version`，但建 tab 后连 websocket 被拒。
根因是"端点通了"不等于"能立刻建 tab 并连上"，中间有竞态，
而 9 份复制代码里没有任何重试。

**自审**
| 维度 | 结论 |
| --- | --- |
| 是否合理 | 合理。同一段逻辑散落 9 处，改一处要改九处 |
| 是否必需 | 必需。CI 偶发失败会让人习惯性重跑，失去信号价值 |
| 偏离初衷 | 不偏离。只重构测试基础设施 |
| 风格一致 | 统一入口，与既有 ui_smoke 风格一致 |
| 工程健壮 | 补 `--no-sandbox`、`--disable-dev-shm-usage`；退避重试 |

**批量替换造成的两次回归（都已修复并复验）**
1. 追加的 import 名字被正则塞进了 `# noqa` 注释里 → NameError
2. 按行范围替换时误删两个脚本的 `failures: list[str] = []` 声明 → NameError

教训：批量改写后必须逐个跑一遍，不能只看"替换成功"的打印。
