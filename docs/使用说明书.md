# 叩门 · 社工个案面谈 AI 陪练舱 —— 产品使用说明书

> 对应毕业设计任务书「预期成果 1：提交软件产品（源代码及可正确安装软件、产品使用说明书）」

---

## 一 系统简介

本系统面向高职社会工作专业学生，提供**可反复练习、即时反馈**的个案面谈陪练环境。
训练内容与评分依据来自民政部行业标准《社会工作方法 个案工作》（MZ/T 094-2017）。

系统把面谈能力拆成六个可观测维度，逐句评分并给出条款依据；
学生可回放复盘、查看成长曲线；教师可查看名下学员数据并写点评；
管理员维护账号、内容与系统运行状态。

**适用场景**：课堂实训、课后自主练习、实习前热身、教师批量化了解班级薄弱项。

**不适用于**：真实个案接案、危机干预实操、正式督导替代。
本系统是**训练工具**，不得用于对真实服务对象进行评估或处置。

## 二 运行环境

| 项目 | 最低要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 10 / macOS 12 / Linux | 开发与验证在 Windows 11 完成 |
| 浏览器 | Chrome 100+ / Edge 100+ | 需支持 ES2020 与 Canvas |
| Python | **3.12** | 后端依赖 3.12 语法特性 |
| Node.js | **18.17+**（推荐 20 LTS） | 仅构建前端时需要 |
| MySQL | **8.0** | 需支持 utf8mb4 |

> **没有 AI 密钥也能完整运行**：所有判定逻辑本地执行，只有长尾语义才调模型。
> 未配置密钥时训练、评分、结算、复盘、成长中心全部可用，服务对象台词取自预置库。

## 三 安装与启动

### 3.1 一键启动（Windows，推荐）

双击项目根目录的 **`start.bat`**。

脚本按顺序执行并自动跳过已完成步骤（幂等，可反复运行）：

1. 检查并启动 MySQL（私有实例，端口 3307，数据目录 `F:\knock-mysql-data`）
2. 执行数据库迁移（`alembic upgrade head`）
3. 若前端产物缺失则构建（`vite build`）
4. 启动后端服务并等待 `/readyz` 就绪
5. 自动打开浏览器

启动成功后访问 **http://localhost:8000**。

### 3.2 手动启动

```bash
# ① 后端依赖（首次）
cd deliverables/backend
python -m venv .venv
.venv\Scripts\activate                # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
copy env.example .env                 # 按需修改 DATABASE_URL

# ② 数据库
mysql -u root -p -e "CREATE DATABASE knock CHARACTER SET utf8mb4"
alembic upgrade head
python scripts/seed.py                # 写入 12 个案例 + 19 张技巧卡

# ③ 启动后端
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# ④ 构建前端（另开终端）
cd frontend
npm ci
npm run build                         # 产物由后端托管，单端口即可访问
```

### 3.3 首次使用前：准备账号

系统**不开放自助注册**（对应「账号由教务统一创建」的教学管理设定）。
首次部署后需创建账号，二选一：

- **方式 A（推荐）**：运行演示账号脚本

  ```bash
  python work/seed_demo_accounts.py
  ```

  将创建：学生 `student01` / `student02`、教师 `teacher01`、管理员 `admin01`。

- **方式 B**：用管理员账号在「管理后台 → 账号管理」逐个创建。

### 3.4 默认账号

| 角色 | 用户名 | 密码 | 登录后进入 |
| --- | --- | --- | --- |
| 学生 | `student01` | `Student@12345` | 训练首页 |
| 学生 | `student02` | `Student@12345` | 训练首页 |
| 教师 | `teacher01` | `Teacher@12345` | 班级看板 |
| 管理员 | `admin01` | `Admin@12345` | 管理后台 |
| 访客 | 登录页「以访客身份浏览」 | 无 | 只读浏览 |

> **安全提示**：正式部署前必须修改以上默认口令，并替换 `.env` 中的 `JWT_SECRET`。
> 生产环境（`APP_ENV=prod`）下若仍使用默认密钥，服务会拒绝启动。

## 四 学生端使用流程

### 4.1 登录

打开 http://localhost:8000 → 点右上角「登录 / 注册」→ 输入用户名密码。

登录后顶栏右侧显示**角色徽标**（学生 / 教师 / 管理员），导航栏按角色裁剪：
学生可见 9 项（首页、服务对象、面谈训练、阶段结算、复盘报告、成长中心、知识库、关于与声明、设置）。

首次登录会自动播放 **12 步**引导（教师/管理员不自动播放），可用顶栏「? 引导」重放，或按 `Esc` 跳过。

### 4.2 选择服务对象

进入「服务对象」页，系统提供 **12 类**服务对象（`W-01` 至 `H-12`），
涵盖空巢老人、失独家庭、青少年厌学、残障人士、职场压力等典型个案类型。

**三档难度**直接决定服务对象的阻抗强度与提示密度：

| 难度 | 英文标识 | 特点 | 适用 |
| --- | --- | --- | --- |
| 简单实习 | NOVICE | 阻抗弱、提示与快捷话术全开 | 第一次接触 |
| 标准实训 | STANDARD | 真实阻抗强度、快捷话术减半 | 课堂实训默认 |
| 挑战督导 | SUPERVISOR | 强阻抗、提示关闭、需要稳定结构 | 有一定基础后 |

点击任一角色卡片进入面谈室。

### 4.3 面谈训练

面谈分**三个阶段**推进，每阶段结束可提交结算：

1. **建立关系**：自我介绍、说明来意、建立信任
2. **问题探索**：澄清困境、共感回应、识别需求
3. **评估介入**：商定目标、给出建议、必要时转介

**输入方式**：
- 在底部输入框逐句键入，按 `Enter` 发送（`Shift+Enter` 换行）
- 点快捷话术按钮快速插入常用表达（难度越高可用条数越少）
- 右侧「技巧提示」显示当前阶段的建议做法与对应条款

**实时反馈**：每句话提交后，右侧评分面板即时更新六维得分，
逐句点评会指出「共情到位」还是「越界评判」，并标注依据的条款编号。

### 4.4 危机内容处置

当输入内容命中危机表述（如自伤、自杀、绝望表达）时：

- 系统**立即中止当前对话**，不再继续扮演服务对象
- 弹出危机提示卡，说明触发的表述与应对建议
- 引导完成转介登记与上报流程

**这是系统的硬性设计**：危机识别由本地规则短路，**不进入模型调用**，
避免因网络或模型延迟导致风险处置被拖延。训练中请认真对待每一次危机提示。

### 4.5 阶段结算与复盘

- **阶段结算**：每个阶段结束点击「提交本阶段」，查看该阶段得分构成、
  命中的评分规则与改进建议。三段成绩累计为整场成绩。
- **复盘报告**：整场结束后自动生成三段式复盘——
  「做对了什么」「哪里失衡了」「下一场怎么改」，可导出留存。

> 只有**点了「提交本阶段」**的成绩才会写入训练记录并进入成长中心。
> 中途退出不会留下记录。

### 4.6 成长中心

汇聚四类成长视图，全部来自本人真实训练记录：

| 视图 | 内容 |
| --- | --- |
| 六维能力雷达 | 六个维度的均值对比，最弱项以朱红标出 |
| 综合分曲线 | 每次训练的总分走势，标注最高/最低/均值 |
| 训练热力图 | 近 18 周每天的训练强度 |
| 剧本完成度 | 12 个案例各自的练习次数与最好成绩 |

**老师点评**区块展示教师对本人的点评（含「表现良好 / 需关注 / 需干预」等级），
首次打开后自动标记为已读。

### 4.7 知识库

提供 **19 张面谈技巧卡** 与 **12 条伦理守则**，支持三种检索方式（可叠加）：

- **关键词**：匹配标题、正文、条款来源
- **适用案例**：筛选"这张卡该在哪个服务对象身上用"
- 六维能力维度：按同感、提问等维度筛选

点卡片右下角「去练习 →」可直接跳转到对应案例的训练页。

### 4.8 访客模式

未注册用户可点「以访客身份浏览」只读访问案例库与知识库，**不能训练**。
访客账号由系统即时创建，不占用教学账号配额。

## 五 教师端使用流程

### 5.1 登录与落地

用教师账号登录后**直接进入「班级看板」**，无需在菜单里寻找。
顶栏导航只有 4 项（班级看板、知识库、关于与声明、设置）。

### 5.2 班级总览

显示四项班级指标：**学员数、训练次数、班级均分、最薄弱维度**。

下方「名下学员」列表显示每位学员的训练次数、均分、账号状态与最近登录时间，
点击任意一行进入该学员的画像。

**绑定学员**：在右侧输入学员用户名后点「绑定」，该学员即归入名下。

> 教师只能看到**自己名下**学员的数据。跨班查询接口返回空集（不报错），
> 越权访问返回 403。管理员可查看全部学员。

### 5.3 学员画像

五个核心指标（训练次数、平均分、总轮次、累计时长、最薄弱维度），
外加六维雷达图、14 天进步曲线、练习过的案例分布、训练记录列表。

**训练记录可直接点评**：点某条记录右侧「点评」，选择等级
（表现良好 / 需关注 / 需干预）并填写内容，点「发布」。
学员会在成长中心的「老师点评」中看到。

### 5.4 训练趋势

班级 14 天均分走势（折线 + 训练次数柱状，含均值虚线）、
班级六维均值条形图（最弱项标红）、案例练习分布。

### 5.5 内容查阅

检索技巧卡与伦理守则作为教学参考。与训练次数无关，纯查阅。

### 5.6 导出成绩

点页面右上「导出成绩 CSV ↓」，下载班级成绩单。

- 一次训练一行，含六维明细、难度、时长、是否使用 AI、提交时间
- 带 UTF-8 BOM，**Excel 双击直接打开，中文不乱码**
- 只导出**已结算**的记录
- 只含本人名下学员，不含他人成绩

## 六 管理端使用流程

管理员登录后直接进入「管理后台」，共 7 个标签页。

### 6.1 运行概览

账号总数、教师数、训练会话、训练记录、24h AI 调用、服务可用率六项指标。

**AI 服务状态**展示密钥是否配置、模型链、日调用上限、累计调用，
以及「走模型 / 规则降级」比例与平均响应时间。

> **可用率口径**：= 未报错请求占比（含降级）。规则模式下降级是**预期行为**，
> 不计为失败，因此可用率仍显示 100%。
> 另单列 `degraded_count`（降级）与 `error_count`（真失败）便于区分。

下方「最近 AI 调用」逐条展示 purpose、状态、模型、延迟、命中方式。

### 6.2 账号管理

- **新建账号**：填用户名（≥3 位）、密码（≥6 位）、昵称、角色，点「创建」
- **搜索筛选**：按用户名/昵称搜索、按角色筛选
- **隐藏访客**：默认勾选。访客是每次访问即时创建的临时账号，量大且无管理价值，
  服务端默认不返回，避免把真实账号挤出第一页
- **批量操作**：勾选多个账号后可批量启用/停用
- **逐条启停**：停用后该账号立即无法登录（已登录令牌在过期后失效）

> 停用账号、批量停用等**不可逆操作会弹出二次确认**，取消则不执行。

### 6.3 平台趋势

近 30 天均分趋势、**训练频率热力图**（近 18 周，悬停看当日次数）、
平台六维均值、角色分布环形图、案例使用热度。

### 6.4 内容维护

- **技巧卡**：填 ID（如 `T-20`）、标题、分类、摘要后保存；列表可删除
- **案例**：填 ID（如 `X-01`）、姓名、年龄、性别、类型后保存；列表可下架

> 删除技巧卡会从知识库移除；下架案例不再出现在选角列表，但历史训练记录仍可查看。
> 两者都会二次确认。

### 6.5 判定词表

九个词表分组（同感与倾听、开放式提问、评判、建议过早、沉默陪伴、离题、危机级、无望感、毒性积极），
显示每组的基线条数与当前生效条数。基线共 165 条。

- **追加词条**：选分组 → 填词条 →（可选备注）→ 点「追加」，立即生效
- **禁用词条**：在分组行的输入框键入词条后按 `Enter`
- **自定义词条**：下方列表可删除

> **危机与无望感两组受保护**：只能追加，不能禁用。
> 这是安全边界，接口层直接拒绝（403）。

### 6.6 台词节点

按情绪档（低/中/高）与角色维护服务对象台词。

新增的台词优先于代码内置基线；数据库不可用时自动回落到基线，
**不会让对话中断**。

### 6.7 操作审计

记录账号启停、内容增删、词表与台词修改等管理动作，显示操作人、动作类型、
摘要与时间。

> 摘要对 `password` / `token` / `secret` 等敏感字段**自动打码**，
> 审计日志本身不会成为新的泄露面。

## 七 常见问题

### Q1 页面白屏 / 打不开

1. 确认后端已启动：浏览器访问 http://localhost:8000/healthz，应返回 JSON
2. 若返回 `{"ok":true}` 但页面空白，检查浏览器控制台是否有 CSP 报错
3. 前端产物缺失：在 `frontend` 目录执行 `npm run build`

### Q2 登录提示「账号或密码错误」

- 账号不开放自助注册，请确认使用教务创建的账号
- 首次部署若未运行 `work/seed_demo_accounts.py`，需先创建账号
- 管理员可在「管理后台 → 账号管理」重置（停用后重建）

### Q3 顶栏显示「规则模式」还是「AI · 模型名」

- **AI · glm-4-flash-250414**：已配置密钥，四类 AI 能力在线
  （意图判定、服务对象台词、六维评分、三段式复盘）。
- **规则模式**：未配置密钥或密钥失效。这是**正常降级状态**——
  训练、评分、结算、复盘全部可用，只是服务对象台词来自预置台词库，
  评分走本地规则。

配置方法：在 `deliverables/backend/.env` 中设置 `GLM_API_KEY` 后重启后端。
可用模型限定为 glm-4-flash-250414 / glm-z1-flash / glm-4.7-flash，
默认按此顺序降级（实测延迟 0.9s / 2.1s / 21.3s）。

**AI 失败时的表现**：界面不会报错。服务对象会回一句可接的台词
（如"……你说。"），评分给出规则分，复盘回落到模板，顶栏如实标注降级原因。

### Q4 训练记录没有出现在成长中心

只有点击「提交本阶段」的成绩才会写入记录。中途关闭页面不会保存。
另外成长中心展示的是**当前浏览器本地记录**，换设备登录不会带过来
（教师端看到的是服务端数据，不受影响）。

### Q5 教师看不到学员数据

- 确认学员已绑定到该教师名下（班级总览右侧「绑定学员」）
- 教师账号的 `teacher_id` 归属关系由管理员维护
- 跨班查询按设计返回空集，管理员可查看全部

### Q6 导出 CSV 用 Excel 打开乱码

文件已带 UTF-8 BOM，正常应不乱码。若仍乱码，用 Excel 的
「数据 → 从文本/CSV」导入并选择 UTF-8 编码。

### Q7 忘记管理员密码

在数据库中将该账号 `is_active` 置回 1，或直接用一个已知账号
通过 API 重置。更稳妥的做法是**始终保留一个备用管理员账号**。

### Q8 服务启动失败，日志显示数据库连接错误

1. 确认 MySQL 在运行：`netstat -ano | findstr :3307`
2. 确认 `deliverables/backend/.env` 中 `DATABASE_URL` 的端口与数据目录一致
3. 运行 `alembic upgrade head` 确认表结构已建

### Q9 如何停止服务

- 一键脚本启动的：关闭后端命令行窗口，或运行
  `powershell "Get-NetTCPConnection -LocalPort 8000 | %{ Stop-Process -Id $_.OwningProcess -Force }"`
- MySQL 私有实例：`mysqladmin -h 127.0.0.1 -P 3307 -u root shutdown`

## 八 数据与隐私说明

- **不采集**真实服务对象信息。所有案例均为虚构人物，用于教学。
- **不记录**对话原文到审计日志。AI 审计只存输入 hash 与长度。
- 训练记录包含六维分数、案例编号、时长与时间，用于成长统计与教师查看。
- 教师点评仅本人、其教师与管理员可见。
- 口令以 Argon2id 哈希存储，不可逆。
- 访客账号不参与教学统计，可定期清理。

**使用边界**：本系统是教学训练工具，不得用于真实个案评估、诊断或处置。
训练中出现的危机提示用于培养风险意识，不能替代真实危机干预流程。
